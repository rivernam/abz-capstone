# 프록시 인자 값은 접속 주소로 찾은 프록시 PC에서 계산한다

설비망 IP가 등록된 PC는 프록시 PC를 거쳐 서버에 접속하고, JVM 인자에 프록시 PC의 설비망 IP를 넣어야 한다. 기준정보에는 어느 PC가 프록시인지 적혀 있지 않다. 대신 서버 로그의 접속 주소가 프록시 PC의 사내망 IP이고, 프록시 PC도 대부분 자기 설비망 IP를 기준정보에 등록하고 자기 자신을 거친다. 그래서 대상 PC의 마지막 성공 접속 주소(없으면 같은 공정·같은 설비 모델 PC들이 3대 이상 일치하는 접속 주소)로 기준정보에서 프록시 PC를 찾고, 그 PC의 설비망 IP와 고정 포트를 값으로 쓴다. 같은 공정·같은 설비 모델의 정상 PC들의 JVM 프록시 값은 교차 검증에만 쓰고, 다수가 다르면 고치지 않는다. 값을 정할 수 없거나 프록시 PC 자체가 이상이면 운영자에게 넘긴다.

## Considered Options

- **같은 공정·같은 설비 모델 PC들의 JVM 값 합의로 정한다**: 현장 관례에 기댄 추정이라 예외 조합에서 틀린 값을 쓸 수 있다. 교차 검증으로만 쓴다.
- **프록시 인자 수정은 운영자에게만 맡긴다**: 내부망 PC의 connection refused가 모두 운영자에게 넘어가 목표 시간을 지키기 어렵다. 기각.
- **문의 본문에 적힌 주소를 쓴다**: 본문은 신뢰하지 않는 입력이다. 기각.

## Consequences

- 서버 로그는 보고 IP와 접속 주소를 둘 다 담아야 한다.
- 설비망 IP를 등록하지 않은 프록시 PC를 거치는 PC는 값을 계산할 수 없어 항상 운영자에게 넘어간다.
