# 프록시 인자 값은 같은 사내망 IP를 쓰는 PC들의 값에서 정한다

설비망 IP가 등록된 PC는 프록시 PC를 거쳐 서버에 접속하고, JVM 인자에 프록시 PC의 설비망 IP를 넣어야 한다. 서버는 접속 주소를 사내망 IP로 보고 (사내망 IP, 설비망 IP)로 PC를 식별하므로, 같은 프록시를 쓰는 PC들은 기준정보의 사내망 IP가 프록시 PC의 사내망 IP로 같다. 그래서 기준정보만으로는 그중 어느 PC가 프록시인지 알 수 없다. 대신 같은 사내망 IP를 쓰는 PC들은 모두 같은 프록시 값을 가져야 하므로, 그중 실행 중인 설비망 PC가 3대 이상이고 JVM 프록시 값이 모두 같을 때 그 값을 쓴다. 같은 공정·같은 설비 모델 관례는 교차 검증에만 쓴다. `internal_ip_pattern`도 이 값에서 계산한다. 값을 정할 수 없거나 프록시 PC로 의심되는 PC가 이상이면 운영자에게 넘긴다.

## Considered Options

- **접속 주소로 프록시 PC를 찾아 그 PC의 설비망 IP를 쓴다**: 같은 사내망 IP를 가진 PC가 여러 대라 프록시 PC를 특정할 수 없다. 기각.
- **같은 공정·같은 설비 모델 PC들의 값 합의로 정한다**: 현장 관례라 예외 조합에서 틀린 값을 쓸 수 있다. 교차 검증으로만 쓴다.
- **프록시 인자 수정은 운영자에게만 맡긴다**: 설비망 PC의 connection refused가 모두 운영자에게 넘어가 목표 시간을 지키기 어렵다. 기각.
- **문의 본문에 적힌 주소를 쓴다**: 본문은 신뢰하지 않는 입력이다. 기각.

## Consequences

- 프록시 하나가 맡는 PC가 적으면(실행 중인 PC 3대 미만) 값을 정할 수 없어 항상 운영자에게 넘어간다.
- 같은 그룹 PC들이 함께 멈추는 프록시 PC 장애에서는 값을 정할 수 없고, 그것이 곧 프록시 장애의 신호가 된다.
